# PR 템플릿 가이드

이 문서는 WePLi iOS 프로젝트에서 사용하는 Pull Request 템플릿을 설명합니다.

> 실제 템플릿 파일: `.github/pull_request_template.md`

---

## PR 템플릿

```markdown
<!--
PR 제목은 다음과 같은 형식으로 작성해주세요.
[Type]: 작업 내용

Type 종류:
- [Feat]: 새로운 기능 추가
- [Fix]: 버그 수정
- [Design]: UI 구현 및 뷰 관련 코드 수정
- [Refactor]: 코드 리팩토링
- [Docs]: 문서 수정
- [Test]: 테스트 코드 추가/수정
- [Chore]: 빌드 관련 파일 수정, 패키지 설정 등
-->
```

## PR 작성 가이드

### PR 제목 형식

```
[Type]: 작업 내용 요약
```

**예시:**
- `[Feat]: 플레이리스트 투표 기능 구현`
- `[Fix]: 로그인 시 토큰 갱신 버그 수정`
- `[Design]: 투표 결과 화면 UI 구현`
- `[Refactor]: NetworkClient async/await 마이그레이션`

### 스크린샷 첨부 기준

| 상황                    | 스크린샷 필요 |
| ----------------------- | ------------- |
| 새 화면/뷰 추가         | ✅ 필수       |
| 기존 UI 수정            | ✅ 필수       |
| UI 버그 수정            | ✅ 필수       |
| 애니메이션 추가/수정    | ✅ GIF 권장   |
| 로직/API 변경           | ❌ 생략 가능  |
| 설정/CI/문서 변경       | ❌ 생략 가능  |
| TCA State/Action 변경   | ❌ 생략 가능  |

### PR 체크리스트

PR을 생성하기 전 확인하세요:

- [ ] PR 제목이 커밋 컨벤션을 따르는가?
- [ ] 작업 요약이 명확하게 작성되었는가?
- [ ] UI 변경 시 스크린샷이 첨부되었는가?
- [ ] SwiftLint/SwiftFormat 검사를 통과하는가?
- [ ] 빌드가 성공하는가?
- [ ] 관련 이슈가 있다면 연결되었는가?
