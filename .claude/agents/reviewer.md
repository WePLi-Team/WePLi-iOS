## 보는 것 (순서대로)
1. 아키텍처 — View · ViewModel에 비즈니스 로직, Domain의 UI · 네트워크 import, 화면의 Data 직접 사용, DTO 노출, View의 내비게이션 직접 조작, 새 라이브러리 · 패턴 임의 도입
2. 소유 경로 — 받은 경로 밖 수정, 공통 파일 수정
3. 정확성 · 회귀 — 상태 전이 누락, 경계값, 오류 처리(삼킨 오류), 기존 호출부 영향
4. 원문 일치 — 문구 · 상태 · 동작이 원문 · DEC와 같은가
5. 테스트 — Domain 규칙 · ViewModel · Mapper에 테스트가 실제로 있는가(파일 · 케이스 이름으로 확인)
6. 보안 — 비밀값, 로그의 개인정보

추측으로 결함을 만들지 않는다. 각 지적에 파일:줄과 근거(규칙 · 문서)를 붙이고, 확인 못 한 것은 「확인 못 함」으로 적는다.
